`studio-docs/build/steps.json` is the **owner doc for step status, dependencies, gates, owner checks and owner inputs**. The app draws it at
https://aaditya-verma.github.io/biology-studio/#progress (Map · Board · Your inputs) and `#step=<id>`, reading it live from the repo.

## Every chat that changes a step
1. Edit the step's row (status, gates, check, log, todo, inputs). Add a new step as a new row at the end of its lane.
2. Add a **run** to the step's `runs` (chat, by, start, end, outcome; commit if known) — every chat that worked on it, even a partial one. **Open run first** (RULES I8 (8)): right after the start checks, write the run with no `end` (outcome `partial`) and push it (route A) or have the owner run `sync.bat` (route B), before any other work; at the end, close it (set `end`, `outcome`, `commit`).
3. `python tools/tracker/check.py --write` — re-derives `unblocks` and formats the file. Then `python tools/tracker/check.py` must PASS (CI runs it).
4. Collaborator chats (the Professor) **don't change `status`** — they set `proposed_by`, `proposed_status`, `proposed_on`; the owner's next chat confirms (sets `status`, deletes the three fields) or rejects (deletes them).

## Row fields
| Field | What |
|---|---|
| `id` | Permanent (RULES A2). Build ids from README (`M1`, `C1`…), `W1`, `X1.<ch>` per chapter, `GATE`, `IB<nn>` = backlog item, Ideation rows `PB UR QB DR`, later `D1 G1`. |
| `title`, `type` | Short name; type = chat type = map lane: Ideation · Build · Research · Content · Episode · Review · Fix · Idea. |
| `chat` | `Bio · <Type> · <Step>` — the name the next chat uses. |
| `status` | idea · planned · ready · in progress · gates · owner check · done · parked · proposed. |
| `needs` / `unblocks` | Step ids it needs; `unblocks` is **derived** (never hand-edit). A need is met when that step is `done` or `owner check`. |
| `lock` | true = the chat takes the build lock (STATUS § Lock). |
| `gates` | `{"G-Eng": "open"|"pass"|"fail"|"na"}`. |
| `check` | `null` or `{"id": "T2", "state": "open"|"pass"|"fail"|"na", "since": "YYYY-MM-DD", "by": "Professor"}` (since/by optional). |
| `decisions` | D-ids. `prompt` = key of `**Ready prompt — <key>**` in master plan §13 (or null). |
| `log` | Last build-log line (short). `todo` = carried pendencies that are not the owner's. |
| `inputs` | What the owner owes: `{"id": "C1.q1", "kind": "decide"|"ask"|"action", "ask", "asked_in", "asked": "YYYY-MM-DD", "answer", "status": "open"|"answered"|"closed", "d": "D-037", "blocks": true?}`. `blocks: true` = the step can't start until answered. |
| `size` | Ideas only: S/M/L from the backlog. |
| `uses` | W2: extra resources it holds while it runs — `gpu`, `research`, or `["prof"]` (a professor-only step: optional, never needed by another step). The lock comes from `lock`. Row = first of lock · gpu · research · owner. |
| `est` | W2: `{"chats": 1, "owner_min": 15, "days": 7}` — chats it takes (default by type: `calendar.chats` or PLAN_DEF), your minutes, and whole days to wait after its needs end (e.g. GATE's 7 days of use). |
| `produces` / `consumes` | W2: named outputs (`dossier-ch10`, `cards-ch6-8`…). A consumed output needs a producer, and the consumer must (indirectly) need that producer. |
| `runs` | W2: `[{"chat", "by", "start": "YYYY-MM-DD[ HH:MM]", "end", "outcome": "done"\|"partial"\|"stopped"\|"fail", "commit", "note"}]` — no `end` = a chat is working on it now (two open runs on the lock or GPU row fail CI). More runs than `est.chats` = slipped. |
| `run` | W3 (D-080): `{"on": "Code"|"Cowork", "why": "…", "override": true?}` — where this step's chat runs and why. Every non-Idea step has one (`--write` fills a missing one from `surfaces`). `on` the rules don't allow → warning, unless `override: true` (then say why in `why`). Not the same as `runs` (the chat history). |
| `improves` | W2: for professor-only steps — what her input would improve (shown on Plan). Inputs take `for: "prof"` + `improves` too; a professor input may not `blocks`. |

## Top-level fields (W2, D-063)
`calendar` = `{"day_min": [Mon…Sun minutes of your chat time], "chat_min": 60, "check_min": 15, "input_min": 10, "off": ["YYYY-MM-DD"], "chats": {type: chats}, "note"}` · `queue` = the plan order for priority (D-047; steps not in it follow in file order). Dates are never stored — the app and `--next` compute them from today.

`surfaces` (W3, D-080; W3F, D-081) = `{"on": ["Code", "Cowork", "split"], "traits": ["tests", "connectors", "artifacts", "owner"], "rules": [{"if": {…}, "on": "Code" | ["Cowork", "Code"], "why": "…", "hard"?, "split"?, "warn"?}], "note"}` — **the one config for where chats run.** The first rule whose `if` all holds gives the suggestion; `if` keys: `lock` (true/false), `uses` (`gpu`, `research`, or `prof` = a professor-only step), `type` (one type or a list), `trait` (in the step's `run.traits`), `files_over` (the step's `run.files` > n). A list in `on` = any of them is fine, the first is the default. **`hard: true`** (on Code only) = Code is required: a step any hard rule matches may not run on Cowork — an **error**, and `override` can't change it. **`split: true`** on a Cowork rule = when a hard rule also matches, the step is **split** (a Code part + a Cowork part) and its `run.handoff` must say what the Code part hands over (no handoff = error). **`warn`** = surfaces that are allowed but warned. Default rules, in order: **Professor → Cowork, Code allowed with a warning** (W3.q1) · GPU, tests, > 15 files, the lock → **Code (hard)** · connectors, artifacts, owner checks/reviews → **Cowork** (split with a hard rule) · ties: Build/Fix/Content/Episode → Code, Research/Ideation/Review → Cowork (W3 answer 2). A step's **`run`** = `{on, why, override?, traits?, files?, handoff?}` — `traits` from `surfaces.traits` and `files` (an estimate of how many files it touches) let the rules see what the step needs. **Code** = Claude Code (desktop app or CLI: app + tools + tests, pushes — route A, or the laptop shell for GPU work); **Cowork** = Claude Cowork (docs and research in the Studio folder, route B with `sync.bat`). The app's `trSurface()` (`src/js/17-plan.js`) and `check.py surface()` give the same answer (`--selftest`, node).

**Draft id clash (error, D-077):** a committed `studio-docs/**/*-draft*.md` whose `Decision: **D-nnn**` line (first 12 lines) names a D-id that DECISIONS uses for another decision, or two drafts propose the same id.

## check.py
`--next` (the schedule: rows, critical path, your inputs ranked — what a chat reads first; `--json`, `--today YYYY-MM-DD`; `--write` refreshes the auto block in STATUS § Next) · `--write` (`--dry-run` shows changes) · `--only <id>` · `--preview` (text board + inputs) · `--debug` · `--strict` (warnings fail) · `--selftest` · `--json` · `--todo-tokens` (TTG: also check to-do lines for `W-title-token`).
`--next` tags every step cell **[Code]** / **[Cowork]**, adds a *Run in:* line for the next step on the lock, GPU and research rows (surface + why), and a *Surface check* line when an open step's `run.on` breaks the rules. Ready prompts carry a *Run in:* line (templates §2).
Errors: unknown ids (steps, D-ids, T-ids, gates, prompt keys, input ids), loops, a started step with unmet needs, ready with a blocking input open, done with open gates/check, stale `unblocks`, the app's `TR_RULES` ≠ the checker's. W3 errors: bad `surfaces` (unknown key, `on` not a list, a rule without `if`/`on`/`why` or with an unknown surface), a `run` that isn't `{on, why, override, traits, files, handoff}`, an unknown `on`, no `why`. **W3F errors:** a hard-Code step on Cowork; split with no `run.handoff`; an unknown trait, `files` not a whole number; a bad rule (`hard` not on Code, `hard`/`split` not true/false, `warn` not a list of surfaces, a `trait` not in `surfaces.traits`). W3 warnings: no `run`, no rule matches, `on` not what the rules allow (without `override`); **W3F:** a warned surface (the Professor on Code — allowed). `--next` tags owner checks with the owner rule's surface ([Cowork]), adds a split step's handoff to *Run in:*, and lists hard and warned steps in *Surface check*.
**Title words (TTG, warning `W-title-token`):** a step's `title` or `chat` word that would split mid-word on `#progress=plan` / `#progress=board` at 640×360 with 125–200 % text (CIR2, 26 Nov: `content/E/sources.json` in a title gave 41 layout-check `midword` issues). Words split at whitespace and `- ‐ – —` (the browser breaks there), with brackets, quotes, backticks and punctuation stripped. A word warns if it is **longer than 12 characters** (`TITLE_TOKEN_MAX`, `# EDIT:`) or **joined** — two letter-runs glued by `/ . _ + \ : @ ＠ =`, or a camelCase hump. **Exempt:** a word whose lowercase form is a GLOSSARY term (bold `**…**` or backticked), and numbers / versions (`640x360`, `v21`, `1.5`). It approximates layout-check's midword rule (`src/js/90-layout-audit.js` §7, measured in the browser). Never an error; CI runs without `--strict`. Fix = plain short words in the title (CIR2 to-do). To-do lines show only on the step page (`ul.tr-todo`, not in the midword audit), so they are checked only with **`--todo-tokens`**, folded into one warning per step.
Warnings: lock older than 24 h, an unconfirmed proposal, a started step without `runs`, **an owner approval with no step** (a DECISIONS row from 22 Nov 2026 that records an approval or pick while no step names its D-id — D-077).
W2 errors: bad `calendar`/`queue`/`est`/`uses`/`runs`, a professor input that blocks or a need on a professor-only step, an output consumed without a producer or without needing it, two open runs on the lock or GPU row. `--selftest` also runs the scheduler on `plan-fixture.json` and compares the app's `trPlan()` (node) with `plan()` on the fixture and on the real file.
