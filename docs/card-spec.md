## 1. Where cards live
- One JSON file per concept: `content/<book>/cards/<id>.json`; the list is `content/<book>/cards/index.json` (`{"spec":1,"book","cards":[{"id","title","status","version"}]}`).
- **Id = the concept id** in `content/<book>/map.json` (`E05.01.01`; README). **Permanent once shipped (A2)** — fix wording freely, never renumber or reuse; a retired card keeps its id with `status: "retired"` and is hidden.
- Addresses: `#studio` (card list, testing mode) · `#studio=<id>` · `#studio=<id>&pane=draft|review|sources&gate=G-Sci` · `#calib` (calibration) · reader (L1): `#cards` · `#card=<id>` · `#deck`.
- Checked by `tools/card-check` (C3) before anything ships; CI runs it on every push.
- Derived look-up file: `content/<book>/sources.json` — registry ids (from `research/source-registry.md`), decision ids (from `claude/DECISIONS.md`), section ids + headings (from `content/<book>/index/tree.json`) and glossary term ids (from `index/terms.json`). Written by `card-check --write-sources`; card-check fails if it is out of date. The app's Studio reads only this file (headings and term names — no book text, G1).

## 2. Fields
| Field | Type | Rule |
|---|---|---|
| `spec` | 1 | this spec's version |
| `id` | concept id | = file name; must exist in `map.json` |
| `version` | int ≥ 1 | stays 1 until first ship, then bump on every change (as scenes, H7) |
| `book` | `"E"` | book code |
| `status` | `draft` · `reviewed` · `shipped` · `retired` | §5 |
| `kind` | `concept` (default, may be left out) · `guide` | optional. **`guide`** = a Part 0 card about the app itself (E00 only, D-050): its facts and misconceptions cite `APP <screen>` and are marked **ⓘ** (§4); everything else follows the normal rules |
| `title` | string | short, our words (G2); may differ from the map name |
| `tier` | `A`–`D` | depth tier (README) |
| `objective` | `{verb, text}` | **one testable objective, one verb** (H1, playbook §4.1): `verb` ∈ §3 list; `text` starts with that verb and joins no second one ("Explain … and order …" fails) |
| `body` | `{<level>: text}` | our-words body per audience level (D-016): `general` and `mbbs` required; `school`, `neet`, `pg` optional. Every sentence carries fact refs `[f1]` / `[f1,f2]` (§4) except a question (ends with `?`, the hook). Word budget per level (§3) |
| `facts` | [fact] | `{id:"f1", text, cite, mark, where:"main"\|"more", decision?, note?}` — one atomic claim each (playbook §3.1), our words, cited (§4) and marked (B7) |
| `terms` | `{new:[term id], known:[term id], exception?}` | glossary ids `E.t.<slug>` from `index/terms.json`; **≤ 3 new** (D2), or **≤ 5 with `exception: "D-0xx"`**, a logged DECISIONS entry saying why (D-037 was the first and was withdrawn: the owner chose to teach the layer names in the Part 0 colour key, D-042); `known` = taught by a prerequisite in the map (not by this card's own scene) |
| `misconceptions` | [mis] | `{id:"m1", wrong, right, cite, mark}` — from the dossier §5 list; refutation = state the wrong idea, then correct it (playbook §3.4) |
| `checks` | [check] | ≥ 2: `{id:"q1", type, prompt, options, answer?, why, tests:"objective", refutes?:"m1"}` — `type` ∈ `mcq` · `order` · the 3D drills `rotate` · `day` · `frames` · `label` · `folded` · `trace` (§2a). `mcq`: `options` 3–5 texts, `answer` = index of the **one** right option; `order`: `options` 3–5 texts listed in the right order, the app shuffles. ≥ 1 check refutes a misconception |
| `adult` | string | optional "this becomes…" line (D4), with fact refs |
| `scene` | `{id, day?}` | optional (D-058): the scene that shows it (`sc-<id>`, scene-spec); the scene's `cards` should list this card. **Leave the key out** when no scene shows the concept yet (Try it then says *Coming soon*, §7) — never point at an unrelated scene. A card with a 3D drill must have a scene (§2a) |
| `remember` | [prompt] | **required, 2–5** recall prompts for the Remember deck (B4, teaching method 12): `{id:"r1", q, a}` — `q` is a question (ends with `?`); `a` is a short answer carrying fact refs `[f1]` to **main** facts only (Remember tests the card, never More); each ≤ 25 words |
| `clinical` | string | optional **Clinical link** (master plan §6; book Clinical Correlates boxes, cite `E05.05 CC`): sentences with fact refs, same sentence rules as `body`; leave the key out when the concept has none (an empty string fails). Factual and humane (D6) |
| `shows_up` | [concept id] | optional **Where it shows up**: 1–6 other concept ids from `map.json` where this idea returns (pick from the concept's `unlocks`/`related`/`recurs`; not itself, no repeats) |
| *later (L3)* | — | AN codes come from `map.json`; Try it = `scene` (L1, §7); Watch it links episode clips at L3 |
| `made` | `{by, role, agent, date}` | who drafted it: person, crew role (playbook §1), which chat/agent, date — editable in Studio's draft pane |
| `review` | `{<gate>: review}` | §5 — `{result:"pass"\|"fail", by, role, agent, date, checklist:{item:true}, lines:{<line id>:"ok"\|"fix: note"}, notes}` — the latest review per gate; earlier rounds stay in `log` |
| `log` | [{date, ev, by}] | status changes and reviews, newest last |

## 2a. 3D drills — Checks driven by the card's scene (V2, D-047, D-054; `trace` V3, D-075)
A drill is a Check like any other: **one right answer**, scored right/wrong, counts toward Understood (§7), logged in `state.answers`. It runs in the card's own scene (`scene.id`) in the one inline viewer (one engine + canvas, D-036 (1)); a drill never names another scene. Every drill works by **keyboard and touch** and has a **text alternative**, so it can be answered without seeing or turning the 3D (no WebGL, screen reader).
- **`show`** — the scene state a drill (or one of its frames/items) opens at: `{day, view?, zoom?, cut?:{axis, at, on}, layers?:{<layer id>: bool}}`. `day` inside the scene's days; `view` = a scene view id (scene-spec §3 `views`) or `{azimuth_deg, elevation_deg}`; `zoom` 0.5–6 (default 1); `cut` as scene-spec §3, plus optional `slab_mm` (0.002–0.5, cross-sections only: keep just a thin slice beyond the cut, so a section still shows only its face — `frames`/`folded`); `layers` only ids the scene has. Labels are off in every drill (they would give the answer); the stamp, scale bar, gizmo and disclaimers stay (B2, H4) — except the masked day of `day` (below).
- **`alt`** — the text alternative: one or two plain sentences (≤ 40 words) saying what the picture shows, **without the answer** (shown folded under the drill as *Describe the picture*; read by screen readers).

| `type` | Name (UI) | Fields | Right when |
|---|---|---|---|
| `rotate` | Rotate to match | `show` (start view) · `target` = a scene view id · `tol_deg` 10–45 (default 25) · `options` 3–5 texts + `answer` (the **words alternative**: "Which view is this?") · `alt` | the live view is within `tol_deg` of the target (angle of the camera rotation between the two views, so turning the picture on screen counts too); or the words answer is right. The start view must be more than `tol_deg` away |
| `day` | Which day is this? | `show` · `options` 3–5 **day numbers** inside the scene's days, distinct · `answer` = index · `alt` | the picked day = `options[answer]`, which must equal `show.day`. While it is asked, the stamp shows **Day ? · stage ? · size ?** (scale bar stays) — the one masked stamp (D-054, B2) |
| `frames` | Order the frames | `options` 3–5 **frames** `{text, show}` listed in the right order (the app shuffles; `text` = that frame's text alternative, ≤ 25 words, distinct); no `answer` | the frames are put in order (↑/↓ buttons, as `order`). Each frame is a still from the scene at its `show` (no labels), with its scale bar |
| `label` | Label it | `show` · `pins` 2–4 `{at, answer}` — `at` = a scene anchor (scene-spec §7 list), `answer` = index into `options`, each pin a different answer · `options` 3–5 label texts (≤ 3 words, distinct; the spare ones are distractors) · `alt` | every pin has its right label (one select per pin; the pin glows while its select has focus) |
| `trace` | Trace a cell | `tracer` = the id of a scene `tracer` part (scene-spec §6) · `show` (the start: `show.day` inside the path's days, where the path is still in the `epiblast`) · `options` 3–5 texts — where the cell can end up (germ layers or structures, distinct) — + `answer` · `ends` = the `in` of the path's last key (the answer key and the scene must agree) · `alt` (the path in plain words of place and day — top, bottom, between, toward the head — never the name of the layer it ends in) · `mask_day` (optional, default `false`: `true` only if the question asks *when*; then the stamp is masked as in `day`) | the pick = `options[answer]`. The marked cell — fill `ctx` with its pattern, an accent ring and the label *Marked cell* (B3: never an accent fill, never the colour of the layer it ends in) — is drawn **only while this drill is open** (never in Try it or stills: the path is the answer). The learner scrubs the day (slider, ◀ ▶ = previous / next path key, Play) from `show.day` to the path's end and turns the view; labels stay off except *Marked cell* and the ruler; the stamp shows day · stage · size (B2) unless `mask_day`. Reduced motion: Play steps from path key to path key. **Not answerable from words alone (D-065):** the right option's text must not appear in the `prompt` or `alt`, and the card's other Checks must not name where *this* cell goes — place the trace where an earlier Check's `why` cannot settle it (G-Learn) |
| `folded` | Folded or not? | `options` exactly **2** texts (e.g. "Folded" · "Not yet folded") · `items` 2–5 `{show, answer: 0\|1, text}` (`text` = the item's text alternative, ≤ 25 words), both answers used | every item is judged right (quick-fire: one still per item, two buttons each) |
- Drills that need the live 3D (`rotate`, `day`, `label`, `trace`) move the one canvas into the Check while the question is open and back to Try it after; `frames` and `folded` use stills of the same engine. If WebGL is missing, the text alternative carries the drill (`rotate` asks the words question; `trace` opens *Describe the picture*, so the path is told in words).
- Spatial verbs (§3) are met by `order`, `frames`, `label` or `rotate`.

## 3. Verbs, levels, budgets
- **Objective verbs:** `explain` `describe` `identify` `label` `locate` `order` `compare` `distinguish` `predict` `name` `trace` `relate`. Spatial verbs (`identify`, `label`, `locate`, `order`) need at least one spatial check (`order`, `frames`, `label` or `rotate`, §2a) — playbook §4.6.
- **Levels and body budgets (words, refs not counted):** `general` 90 · `school` 110 · `neet` 140 · `mbbs` 160 · `pg` 200. Sentences ≤ 25 words (master plan §6). A level's text must make sense alone (B10: terms explained on first use at `general`).
- **New terms ≤ 3 per card** (D2); up to 5 only with a logged exception (`terms.exception`).

## 4. Citations + marks (B1, B6, B7) — `validate_citation`
- Grammar: `cite = sections [" · " sources]` · `sections = sec ("," sec)*` · `sec = E<ch>.<sec> [locator]` or a chapter `E<ch>` · `sources = src ("," src)*` · `src = R<nn>[a-z]{0,2} [locator]` (`R06`, `R05b`, `R05aa` — two letters once a group passes `z`, C2) or a cross-chapter `E<ch>[.<sec>]`. Locators are short words after the id: `CC` (Clinical Correlates box), `Tbl 6.4`, `Fig 6.1`, `CS7`. No ranges (`E05.01, E05.02`, not `E05.01–02`).
- A cite with **no book section** (starts with `· `) is allowed only for ✚.
- `validate_citation(cite)`: every section id exists in `index/tree.json` (chapter ids in its chapters); every `R…` id exists in the registry (`sources.json`). In the app it is `validateCitation()` in `src/js/15-cards.js`; in tools `tools/card-check/citations.py`.
- **Mark rules:** ✔✔ needs a book section + ≥ 1 Tier 1 source · ✔ = book section (Tier 2–3 sources can't lift it) · ⚑ needs `decision: "D-0xx"` that exists in DECISIONS; the card gives the book answer, the newer evidence goes in a `more` fact · ✚ = no book section or beyond it, Tier 1 only, `where: "more"` only, text labelled "beyond Langman" · **≈ blocks** `reviewed` and `shipped`.
- **App cites (guide cards, D-050):** `APP` or `APP <screen>`, screen ∈ Today · Cards · Card · Check · Explain · Deck · Try it · Watch it · Status · Settings · Lessons · Mixed review (the last two added in L2, D-070); mark **ⓘ** ("how the app works"). An APP cite outside a guide card, or ⓘ on anything but an APP cite, is an error. G-Sci checks an ⓘ line against the app as built (design plan §4.8); the owner confirms it in T7. B1's book-section rule covers biology facts; a guide card holds none.
- **Mark suggester** (calibration): decision → ⚑; no book section → ✚; book + Tier 1 → ✔✔; else ✔. It proposes; the reviewer decides (a Tier 1 source can *disagree* — that is a ⚑, which only a person can see). `#calib` and `card-check --calibrate` score it against 5 dossier facts (`cards/calibration.json`); it must get 5/5.

## 5. Status, gates, reviewers (H2)
| Status | Needs | Set by |
|---|---|---|
| `draft` | card-check runs (≈ allowed, as a warning) | maker (Studio or a Content chat) |
| `reviewed` | card-check **0 errors**, no ≈; **G-Sci** and **G-Learn** = pass, every line `ok`, every checklist item ticked; each reviewer's `role` **and** `agent` differ from `made` (a different role, fresh eyes) | Studio, when both gates pass |
| `shipped` | reviewed + **G-A11y** pass (fresh eyes) + **G-Owner** pass (owner, `by` = the owner) | Studio / Content chat after the owner's OK |
| `retired` | — (hidden, id kept, A2) | owner |
- **Any content edit clears every pass and the review ticks** (a pass is for the card as reviewed); failed reviews stay as history. A `reviewed`/`shipped` card goes back to `draft`. Studio does this and says so; a chat editing a card by hand does the same and logs it.
- A new review starts blank; only a standing pass shows ticked.
- Gate checklists (shown on the review card): **G-Sci** — every fact cited + marked · cites point at the right sections · anatomy, timing, scale right vs book + Tier 1 · ⚑ has its D-entry and the book answer · ✚ only in More · no ≈. **G-Learn** — objective is one testable verb · Checks test the objective · ≥ 1 Check refutes a misconception · ≤ 3 new terms, explained at General · body within budget, one idea per sentence · "this becomes…" where it fits (D4). **G-A11y** — plain text alternatives for every visual · Checks work by keyboard + touch · no colour-only cue in text ("the orange layer") · 125 % text fits.
- Review lines (the "approve / fix line by line" rows): **G-Sci** signs every body sentence `body.<level>.<n>`, every fact `f<n>`, every misconception `m<n>`, `adult`, `clinical` and every Remember prompt `r<n>`; **G-Learn** signs `obj`, `terms`, every check `q<n>`, every misconception, every Remember prompt `r<n>` and `shows_up`. G-A11y and G-Owner are checklist only. A line is `ok` or `fix: <note>`; any fix = fail, and the Studio copies a ready `Bio · Fix · <id>` prompt with the notes.
- Checklist item ids (stored in `checklist`): G-Sci `cited sections accuracy flags plus noapprox` · G-Learn `objective checks refutes terms budget adult` · G-A11y `alt input colour text125` · G-Owner `owner`.

## 6. card-check (C3) — `tools/card-check/check.py`
Errors (block): `E-schema` field missing/wrong type · `E-id` id ≠ file or not in map · `E-objective` missing, verb not allowed, not one verb · `E-cite` validate_citation failed · `E-mark` missing/unknown mark or breaks a §4 rule · `E-approx` ≈ in a reviewed/shipped card · `E-ref` body, adult or clinical sentence without a fact ref, a ref to no fact, or a Remember answer without a ref to a main fact · `E-remember` < 2 or > 5 prompts, bad id, `q` not a question, `a` missing · `E-shows` `shows_up` not a list of 1–6 other map concept ids, or repeats · `E-words` body over budget · `E-sentence` > 25 words · `E-terms` > 3 new (> 5 with an exception), an exception not in DECISIONS, or an unknown term id · `E-check` unknown type, < 3 options (2 for `folded`), not exactly one answer, no `why`, `tests` ≠ objective, a drill field missing or of the wrong shape (§2a: `show`, `alt`, `pins`, `items`, frames, day options) · `E-drill` a drill on a card with no `scene`, or a drill that does not fit its scene: `show.day` or a day option outside the scene's days, the `day` answer ≠ `show.day`, an unknown view, layer or anchor, a `rotate` that starts inside its tolerance, a `label` pin answer repeated, a `trace` whose `tracer` is not a tracer part of the scene, whose `show.day` is outside the path's days or where the path is not yet in the epiblast, whose `ends` ≠ the path's last `in`, or whose right option's text appears in its `prompt` or `alt` (D-065) · `E-checks` < 2 checks, none refutes a misconception, spatial verb without a spatial check · `E-mis` misconception field missing or uncited · `E-scene` a given scene not in `scenes/index.json`, or `day` not a number inside its days (`E-schema` if `scene` is there but not an object) · `E-status` status not backed by the gates (§5) or a reviewer = the maker · `E-level` `general`/`mbbs` missing · `E-index` index.json out of step with the files · `E-sources` sources.json stale · `E-kind` a guide card outside Part 0.
Warnings (draft only): `W-approx` ≈ present · `W-terms` a map term of this concept not in the card · `W-scene-cards` the scene doesn't list this card.
card-check reads the scene files (`content/<book>/scenes/sc-*.json`) for drills (V2). Flags (RULES I5): `--only <id>` · `--dry-run` (list what would be checked) · `--debug` (every rule as it runs) · `--preview` (one card's level texts as plain text, fast) · `--json` · `--write-sources` · `--calibrate` · `--parity` (runs the app's `cardCheck()` in headless Chromium on every card and compares error codes).

## 7. How the reader uses a card (L1 — `src/js/18-learn.js`; layout: `build/design-plan.md` §2 Card row, §4.8)
- **Who sees it:** cards with `status` in `CONFIG.learn.show` (reviewed, shipped); testing mode also shows drafts. `retired` is never shown.
- **Order on the card:** title, level toggle (`general` · `mbbs` first, other levels when the card has them; choice saved in `settings.level`) → objective → body (each `[fN]` becomes a small number that opens those facts with cite + mark) → `adult` → `clinical` → misconceptions as *Don't confuse* (✗ wrong, ✓ right) → **Check** → **Can explain** → **Remember** (the prompts, answers folded) → `shows_up` → **More** (`where: "more"` facts, incl. ⚑ newer evidence and ✚; folded, with a count — left out when the card has none) → **Sources** (open: the book sections the card cites, each with its section name from `sources.json`, then the registry sources it cites, each with its name; a guide card says *App facts (ⓘ) — no book source*; below, folded, every main fact with its cite + mark and the marks key). A heading is never shown without content under it. Try it (the `scene` at `scene.day`) and Watch it ("Coming soon" until L3) sit beside or above the text by device class. **A card with no scene (D-058)** shows Try it as a *Coming soon* strip like Watch it, and the card is one reading column on every class (no 3D column; desktop keeps the card rail).
- **Opened from a lesson (L2, D-070):** `#card=<id>&lesson=<ch>[&step=<kind>]` adds the lesson bar at the end of the head (and a short one at the end of the text) — format and behaviour in `docs/lesson-spec.md` §6. The card itself is unchanged.
- **During a Check run (D-053):** from *Start the Check* until the run ends, the card text folds away — body, *This becomes…*, Clinical link, *Don't confuse*, Can explain, Remember (prompts + answers), Where it shows up, More and Sources — so the Check is recall, not reading. The objective, Try it and the Check stay; Try it's labels and hover names are off for the run and *Open full 3D* is hidden (they would answer it — G-Learn, D-056). In their place one line: *Card text hidden during the Check* + **Read again**, which opens the text and **ends the run unscored** (no run counted; the answers already given stay in `state.answers`); *Start the Check* begins a fresh run. When the run ends (result shown) the text comes back. Leaving the card ends an open run unscored (other screens show labels).
- **Statuses (B4)**, saved in `state.cards[<id>]` as the first time each was reached: **Read** — the card was open `CONFIG.learn.readMs` (1.5 s); **Understood** — every check right in one run (mcq and order options are shuffled each run; a miss shows the right answer and the `why`); **Can explain** — after Understood, the learner explains the objective aloud, opens the model answer (the body at their level) and confirms. Statuses never go back. Every answer is kept in `state.answers` as `card:<id>:<q>`.
- **Drills (§2a, V2):** shown in the Check like any question, one at a time. `rotate`, `day`, `label`, `trace`: the inline viewer (stage + a drill panel: turn buttons, Reset view, Check my view / the selects; `trace` adds the day row — ◀ slider ▶ Play — and its options below the stage) sits inside the Check; Try it shows a short note until the drill ends, then gets its own view back (day, camera, cut, layers). `frames`, `folded`: stills (the scene at each `show`, labels off, scale bar drawn in). Each drill has *Describe the picture* (its `alt`, folded) and `rotate` has *Answer in words instead*. Feedback = ✓/✗ + the right answer (`day`: the day; `trace`: where it ends up; `label`: each pin's label; `frames`: the right order; `folded`: each item) + `why`; then the stamp is unmasked.
- **Remember deck:** on Read, each `remember[]` prompt becomes `state.deck["<id>#<r>"]`, first due after 1 day; *Got it* moves it on (then 3, then 7 days, then every 7 — `CONFIG.learn.deckDays`), *Not yet* sends it back to 1 day and repeats it once at the end of the session. Today shows the number due; the card's Remember line says when its next prompt is due (*Due today* · *Due tomorrow* · *Due 24 Nov*). A card change never resets the deck (ids are permanent, A2); a prompt removed from a card drops out of sessions.
