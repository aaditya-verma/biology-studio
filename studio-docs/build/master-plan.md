## 4. Content model
Ids, book codes, tiers, audience levels, threads, marks, gates → `claude/README.md`. **Concept** (K1) = a row in the concept map; it becomes a card with the same id. Card = one screen + More: **objective** · idea · 3D view · Watch it · Try it · Remember · More (incl. "Newer evidence" / "beyond Langman") · Clinical link · Where it shows up · Check · Sources · AN code. Episode (60–180 s default) = cold open ≤ 10 s (question/mystery) → terms strip → 3 beats (ABT, one objective each) → "this becomes…" → recap → 2-question Check; core ×2 / support ×1. **Audience profile** per episode: level (General · School · NEET · MBBS · PG), depth tier, type (explainer · story · quick recap · short), format (16:9 · 9:16), length, language; cuts `S1E01-gen`, `S1E01-short`. Story formats: Journey · Mystery · Factory · Character · Countdown; Season 1 question: *How does a flat disc become a body?*

## 5. K1 — Concept map, explorer, roadmap (D-017)
- **Inputs (I1):** `content/E/index/` — `tree.json` (sections + pages + boxes), `terms.json` (265 glossary terms → sections), `xrefs.json` (section links + chapter × chapter shared terms), `timeline.json` (days, numeric tables). Section tables: `curriculum/book-index-part1.md` / `-part2.md`.
- **`curriculum/concept-map.md` + `content/E/map.json`:** every chapter → subheader → concept. Per concept: id, name, tier, threads, day/stage range, germ layer, system, AN code, importance (core / exam-high / supporting / detail), prerequisites, related concepts, common misconceptions, book pages (locator only, no text).
- **Crosstabs:** Concept × Chapter (where it recurs) · Concept × Day/Carnegie stage · Concept × Germ layer · Concept × System · Chapter × Chapter (shared concepts) · Tier × Chapter (coverage) · Prerequisite graph.
- **Clickable explorer** (claude.ai artifact first; later the app's Book map): Part › Chapter › Subheader › Concept drill-down; crosstab heatmaps where every cell opens its concepts; search; filters (tier, thread, layer, system, importance); concept page (definition in our words, where it appears, prerequisites, unlocks, cards/episodes status); deep links `#concept=E05.02.01`, `#x=layer&y=day`; `?debug=map` and ✎ on every node (RULES I5–I6). Phone and laptop layouts per §8; accessibility per RULES H5.
- **Built 17 Nov 2026 (D-028):** 314 concepts; explorer https://claude.ai/artifact/Bg2DUqLgdqC3NgroWMEvin (artifact links `#c-…`, `#x-…`, `#debug`); builder `tools/map/`.
- **`curriculum/roadmap.md`:** all important concepts in a step-by-step order — waves (foundations → Part 1 → systems) → seasons → episodes, using prerequisites and unlock counts; each wave lists its X1/C1/P1 work and owner checks. Updated after every use gate.

## 6. Content production — Research → Draft & review
K1 rows + X1 dossier for the chapter → pick concepts → write objectives → Studio drafts from the book + dossier (own words, cited, marked; refutes listed misconceptions) → validator (citations exist, marks present, ⚑ has a D-entry, ✚ only in More/Tier D, ≤ 25-word sentences, ≤ 3 new terms, glossary coverage, one right answer, Check matches objective) → **fresh-eyes review** (G-Sci, G-Learn, G-A11y) → owner reviews line by line → any ≈ left? yes → redraft; no → approved, permanent id, imported. Calibrate first: ≥ 90 % of glossary terms placed (I1: 98.9 % by text search, as the PDF has no Index — D-026).

## 7. Video production (local-first, D-014; craft per playbook §5–7)
Brief + audience profile → objectives → cited script (ABT) → table read (scratch TTS) → storyboard → shot list → scenes (checked against R01/R02) → **animatic in three.js with scratch voice** → gates G-Sci, G-Learn, G-Story, G-Art → final render on the laptop GPU (tool from M1; `--preview` first) → final voice (pronunciation dictionary, 130–150 wpm) + mix (−14 LUFS) + captions/transcript (drift < 100 ms) → ffmpeg assemble (NVENC H.264; x264 veryfast fallback) → QC (G-Eng, G-A11y, General-cut clarity, episode checklist) → render manifest → publish to Drive + catalog + card clips → measure (recall, completion, drop-off). Meshes procedural where possible; glTF (.glb) between Blender and three.js; third-party assets only with approved licences (Z-Anatomy adult meshes in rendered video only, D-021).

## 8. Design system & UI
Device classes `dev-p / pl / tp / tl / d`. DrumPath tokens + germ-layer tokens with patterns on a colour-blind-safe base (`--g-epi`, `--g-hypo`, `--g-ecto`, `--g-meso`, `--g-endo`, `--g-crest`, `--g-ctx`) + plum accent `--accent` for "look here" — values D-031. Every place has an address (`#concept=`, `#card=`, `#ep=…&t=`, `#map=`, `#day=`); Back/Forward/Up via history; Android Back stays in-app. Screens: Today · **Explorer / Book map** (§5) · Card · Episode player (transcript, chapters, card rail, quiz, fix-it, captions, reduced motion) · 3D viewer (rotate, day scrubber, layers, labels, cut plane, axis gizmo, scale bar, depth cues) · Progress · Studio. Pinch-zoom on; PWA from day 1. Testing mode adds the debug overlay and ✎ edit hooks (RULES I5–I6). Detail → `build/design-plan.md` (A0).

## 9. Learning engine
Objectives per card/beat · statuses (timestamps, merged) · Remember deck 1/3/7/21/60 · Check types (MCQ with Don't-confuse distractors, label, order frames, which day/layer, rotate to match) · episode quiz → streak + recall only · fix it with cards · Ready to watch · weak-spot profile · Today (On the go ≤ 5 min / Study 15–30 min) · gentle streak · recall quotient (per story format and audience profile).

## 10. Data, storage, privacy, copyright
IndexedDB `biostudio` (`state`, `answers`, `files` LRU). Drive (`drive.file`, Picker; fresh Google Cloud project "Biology Studio"): `book/ index/ assets/ renders/ audio/ backup/ research/`. Merge: answers union, furthest status, newer settings, tombstones. Testing mode on claude.ai + `?test=1`. No analytics. Copyright → RULES §G. YouTube per episode later = a separate decision.

## 11. Quality
Seven review gates (playbook §2, RULES H2) · citation + mark check · id check · map check (every concept has tier, thread, locator; no orphan prerequisites) · card validator · scene validator · still regression · layout C8+ · accessibility (H5) · loudness (H6) · performance budgets (H8) · render manifests (H7) · playback (≤ 4 s start, drift < 100 ms) · storage · Guide C10 · coverage report (AN competencies and roadmap items with no card) · **debug flags off by default and ✎ hooks resolve to the right file (I5–I6)** · **doc freshness (I2, I4)**. CI on GitHub Actions runs the automatic ones. Owner checks in `build/owner-test-checklist.md`; no next build until the last one is done.
