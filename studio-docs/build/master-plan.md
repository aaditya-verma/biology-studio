## 4. Content model
Ids, book codes, tiers, audience levels, threads, marks, gates → `claude/README.md`. **Concept** (K1) = a row in the concept map; it becomes a card with the same id. Card = one screen + More: **objective** · idea · 3D view · Watch it · Try it · Remember · More (incl. "Newer evidence" / "beyond Langman") · Clinical link · Where it shows up · Check · Sources · AN code. Episode (Lesson 6–10 min, segments 60–120 s, learner-paced ideas 20–60 s; Short ≤ 60 s; D-107) = cold open ≤ 10 s (question/mystery) → "Meet the parts" primer (Lessons) → ideas (ABT, one objective each) → "this becomes…" → recap → 2-question Check; core ×2 / support ×1. **Audience profile** per episode: level (General · School · NEET · MBBS · PG), depth tier, type (lesson [was explainer, D-046] · story · quick recap · short), format (16:9 · 9:16; Lesson vs Short → `build/visual-style.md` §10), length, **language (English default · Hinglish · Hindi)**, **host (cell/embryo character default · animal · stylised human · none)** (D-032); cuts `S1E01-gen`, `S1E01-short`. Short grammar + host rules → playbook §5b. Story formats: Journey · Mystery · Factory · Character · Countdown; Season 1 question: *How does a flat disc become a body?*

## 5. K1 — Concept map, explorer, roadmap (D-017)
- **Inputs (I1):** `content/E/index/` — `tree.json` (sections + pages + boxes), `terms.json` (265 glossary terms → sections), `xrefs.json` (section links + chapter × chapter shared terms), `timeline.json` (days, numeric tables). Section tables: `curriculum/book-index-part1.md` / `-part2.md`.
- **`curriculum/concept-map.md` + `content/E/map.json`:** every chapter → subheader → concept. Per concept: id, name, tier, threads, day/stage range, germ layer, system, AN code, importance (core / exam-high / supporting / detail), prerequisites, related concepts, common misconceptions, book pages (locator only, no text).

- **Clickable explorer** (claude.ai artifact first; later the app's Book map): Part › Chapter › Subheader › Concept drill-down; crosstab heatmaps where every cell opens its concepts; search; filters (tier, thread, layer, system, importance); concept page (definition in our words, where it appears, prerequisites, unlocks, cards/episodes status); deep links `#concept=E05.02.01`, `#x=layer&y=day`; `?debug=map` and ✎ on every node (RULES I5–I6). **Layouts for all five device classes per §8a** (phone drill-down → desktop three panes) — the K1 explorer was built before D-033 (phone + laptop only); A0 brings it up to §8a when it ports it as the Book map. Accessibility per RULES H5.

- **Embryo map (D-071, steps K2 → K3 → K4):** the app's Book map (`#map`) becomes one connected map — rings = day after fertilization (CS1–CS23 stretched, fetal weeks squeezed; Toolkit E00 + E01 at the centre), wedges = organ system, dot colour = germ layer (B3), ◆ = a birth defect at the start of its sensitive period; levels Parts → Chapters → Sections → Concepts; a panel with needs · unlocks · comes back in · becomes · goes wrong as · episodes · AN · mark · misconceptions; tap once = links, twice = open; day slider, path to a topic, colour modes (germ layer · my progress · exam-high + AN · tier); Side view = a three.js cone, height = day. ## 6. Content production — Research → Draft & review
K1 rows + X1 dossier for the chapter → pick concepts → write objectives → Studio drafts from the book + dossier (own words, cited, marked; refutes listed misconceptions) → validator (citations exist, marks present, ⚑ has a D-entry, ✚ only in More/Tier D, ≤ 25-word sentences, ≤ 3 new terms, glossary coverage, one right answer, Check matches objective) → **fresh-eyes review** (G-Sci, G-Learn, G-A11y) → owner reviews line by line → any ≈ left? yes → redraft; no → approved, permanent id, imported. Calibrate first: ≥ 90 % of glossary terms placed (I1: 98.9 % by text search, as the PDF has no Index — D-026).

## 7. Video production (local-first, D-014; craft per playbook §5–7)
Brief + audience profile (incl. language + host) → objectives → cited script (ABT) → table read (scratch TTS) → storyboard → shot list → scenes (checked against R01/R02) → **animatic in three.js with scratch voice** (host as placeholder) → gates G-Sci, G-Learn, G-Story, G-Art → final render on the laptop GPU (tool from M1; cinematic look per playbook §6; `--preview` first) + host shots (tools from M1b) → final voice (pronunciation dictionary, 130–150 wpm) + mix (−14 LUFS) + captions/transcript (drift < 100 ms; kinetic for Shorts) → ffmpeg assemble (NVENC H.264; x264 veryfast fallback) → **renditions per §8a** (720p phones; 1080p tablet/desktop rung if M1 allows) → QC (G-Eng, G-A11y, General-cut clarity, episode checklist, **plays well on phone, tablet and laptop**) → render manifest → publish to Drive + catalog + card clips → measure (recall, completion, drop-off). Meshes procedural where possible; glTF (.glb) between Blender and three.js; third-party assets only with approved licences (Z-Anatomy adult meshes in rendered video only, D-021).
